# Install Pericope on a new Oracle Autonomous Database

This folder sets up a fresh Autonomous Database (ADW or ATP, 23ai or 26ai) for Pericope. You get:
- the tables of the old `PERICOPE_ERM` schema
- the app's migrations
- demo data in every table
- REST endpoints and an OAuth client for the API

**Tested** end to end on Oracle Database 23ai Free:
- 216 tables, 1,379 demo rows, 247 foreign keys and 0 invalid objects, with no errors.
- Re-running the whole install gives the same result.

The ORDS steps (REST endpoints and OAuth client) can only run on Autonomous Database.

## Quick path: one script

1. **Create the schema (once).**
   1. Open the database in the OCI console → **Database actions** → **SQL**, signed in as **ADMIN**.
   2. Open [`00_create_schema.sql`](00_create_schema.sql) and replace `CHANGE_ME_Strong_Passw0rd` with a strong password.
   3. Press **Run Script** (F5).
2. **Sign in as PERICOPE_ERM.**
   1. Sign out of Database Actions.
   2. Sign in again with user `PERICOPE_ERM` and the password from step 1. The sign-in page URL ends in `/ords/pericope_erm/...`.
3. **Run the install.**
   1. In **SQL**, open [`install_all.sql`](install_all.sql) (drag the file in, or paste it).
   2. Press **Run Script** (F5).
   3. Wait a few minutes. The **Script Output** pane shows `===== Step 01` … `Step 08`.
   4. **It erases everything in the PERICOPE_ERM schema first.** It refuses to erase anything when signed in as ADMIN.
4. **Copy the OAuth client into `api/.env`.**
   1. The **Script Output** (or **DBMS Output**) pane shows `ORDS_CLIENT_ID=…` and `ORDS_CLIENT_SECRET=…`. The secret is shown only once.
      If it isn't there, run [`09_oauth_client.sql`](09_oauth_client.sql) on its own: it creates the client again and prints both.
   2. Put them in `api/.env` on your server, never in chat or git:
      ```
      ORDS_BASE_URL=https://<your-adb-host>/ords/pericope_erm
      ORDS_TOKEN_URL=https://<your-adb-host>/ords/pericope_erm/oauth/token
      ORDS_CLIENT_ID=<CLIENT_ID>
      ORDS_CLIENT_SECRET=<CLIENT_SECRET>
      ```
   3. `<your-adb-host>` is in the address bar of Database Actions, for example `<id>-soumitadw.adb.<region>.oraclecloudapps.com`.
5. **Check it.**
   1. Restart the API.
   2. Run `cd api && npm run check:ords-anon`. Every table must answer **401** without a token.
   3. Open `/ready` on the API, which should show `"database":"ok"`.
   4. Sign in to the app: the dashboard, register, heat map and reports show the demo company's data.

## What the script runs, step by step

You can also run the files one by one, in this order, in the same way.

| Step | File | What it does |
|---|---|---|
| 00 | `00_create_schema.sql` | **As ADMIN, once.** Creates the `PERICOPE_ERM` user and REST-enables it (`/ords/pericope_erm/`) |
| 01 | `01_drop_all.sql` | Erases every table, view, sequence and package in the current schema (refuses in ADMIN) |
| 02 | `02_tables.sql` | 202 tables from the old schema's DDL |
| 03 | `03_foreign_keys.sql` | 235 foreign keys, added after all tables exist |
| 04 | `04_app_alignment.sql` | Small fixes so the old tables accept what the app writes (below) |
| 05 | `../migrations/V1` … `V5` | The app's migrations: scoring columns, module tables (controls, policies, incidents, vendors …), views, alignment |
| 06 | `../seed/demo_data.sql` | Demo controls, policies, incidents, vendors, BCP plans, scenarios, risk appetite, KRIs, approvals |
| 07 | `07_mock_data.sql` | Demo data for every other table (below) |
| 08 | `08_finish.sql` | Re-points the control keys, REST-enables the 62 tables the API uses, creates the OAuth client `pericope-api` and prints its id and secret |
| 09 | `09_oauth_client.sql` | **Only if needed:** re-creates the OAuth client and prints a new id and secret |

`install_all.sql` is these files (01 → 08) joined together.

### How the old DDL was changed

The source is the export you pasted from the old database: [`source/pericope_erm_ddl.tsv`](source/pericope_erm_ddl.tsv). `tools/build.mjs` turns it into steps 02, 03 and 08:

- **The `"PERICOPE_ERM".` prefix is removed**, so it installs into whichever schema you are signed in as.
- **Storage, tablespace and LOB clauses are removed.** Autonomous Database manages these itself.
- **Foreign keys are moved to step 03.** In the export some tables reference tables that come later in the alphabet.
- **Identity columns become `GENERATED BY DEFAULT ON NULL`.** The demo rows can then carry fixed ids, and new rows still get ids automatically. Step 07 moves each identity past the demo ids.
- **Two foreign-key columns that defaulted to `0` now default to `NULL`:** the parent org unit and the parent mitigation plan. There is no row 0, so every new row would otherwise have failed.
- **Nine scratch/test tables are left out:** `HTMLDB_PLAN_TABLE`, `PERICOPE_UC_RESULTS`, `PERICOPE_UC_TEST`, `PER_LOOKUP_MASTER_ERR$`, `PER_LOOKUP_MASTER_ERR$1`, `TEMP_DEBUG_OUTPUT`, `TEST`, `TMP_TEST_RESULTS`, `T_TEST_RESULTS`.
- Annotations, JSON columns, virtual columns and CHECK constraints are kept as they were.

### App alignment (step 04, and migration V5 for an existing database)

- **`PER_TRN_RISK_MONITORING`:**
  - Gets `IDENTIFY_RISK_UUID` and `ASSESSMENT_REFERENCE_NUMBER_UUID`. The app links each action to its risk with them.
  - `ROOT_CAUSE` becomes text. The action-plan form saves a sentence there.
- **`PER_TRN_INHERENT_RISK_ASSESSMENT`** gets `CREATED_ON` / `CREATED_BY`. The assessment history then shows when, and by whom, each assessment was saved.
- **The risk register's approval-status check** also allows `IN_REVIEW` and `PENDING`, which the approval workflow uses.
- **Step 08 re-points two foreign keys to the control library `ERM_MST_CONTROL`:** applied controls and monitoring items. That is what the app stores there; the old keys pointed at `PER_MST_CONTROL_REGISTER`.

### The demo data

- **A fictional enterprise, "Meridian Group"**: 10 departments (Finance, HR, Sales & Marketing, Procurement & Supply Chain, Manufacturing & Operations, IT, Legal & Compliance, Customer Service, R&D, Risk & Internal Audit) and ERP process areas (Order to Cash, Procure to Pay, Record to Report, Hire to Retire, Plan to Produce, Inventory & Logistics …). Every person is invented and every e-mail address ends in `@example.com`.
- **Hand-written rows** (`tools/mock-curated.mjs`) for everything the app shows:
  - org units, people and roles
  - risk taxonomy, likelihood and impact scales, processes and the control taxonomy
  - three quarterly RCSA cycles
  - **17 risks** across the departments: approved, submitted, draft, one rejected and one not yet rated
  - inherent assessments, applied controls, monitoring actions, a mitigation-plan hierarchy
  - KPIs with six months of actuals
- **Generated rows** (`tools/mock.mjs`): 5 per table for the other ~160 tables, mostly the old APEX app's governance, audit, vendor and AI tables. They respect each table's types, lengths, NOT NULL, CHECK lists and ranges, unique keys and foreign keys.
- **Not filled:**
  - `ERM_TRN_AUDIT_LOG` (audit history must be real)
  - `WF_DEBUG_LOG`
  - `ERM_MST_APP_SETTING` (the app uses its defaults)

## If something goes wrong

- **No client id/secret printed**, or you lost the secret: run `09_oauth_client.sql` alone, as PERICOPE_ERM. It deletes and re-creates
  the client `pericope-api` and prints the new id and secret (then update `api/.env`). If it prints
  `Could not create the OAuth client` with two errors, create the client in Database Actions instead:
  1. Go to **REST** → **Security** → **OAuth Clients** → **Create**.
  2. Grant type **client credentials**.
  3. Roles: `oracle.dbtools.role.autorest.PERICOPE_ERM`.
- **The API gets 401 even with a token:** the client is missing that role. Add it in the same OAuth Clients screen.
- **Warnings** are also written to a table:

  ```sql
  SELECT logged_on, message FROM pericope_migration_log WHERE log_level = 'WARNING' ORDER BY logged_on;
  ```
- **To start again**, run `install_all.sql` again. It erases and rebuilds everything.

## Changing the scripts

Edit the source or the generators, never the generated `.sql` files. Then rebuild:

```bash
npm run db:install
```

CI fails if the generated files are out of date.
